# 语音录入会话化改造设计（itinerary）

日期：2026-10-15
状态：已与需求方确认（对话逐条拍板）

## 意图与动因

语音录入目前是**组件级**状态：悬浮按钮与当日弹框各持一份独立的 `useVoiceRecorder` 实例（各自的 phase / 麦克风流 / 防抖锁）。这导致三个已确认的问题：

1. **两处同时录音**：浏览器允许并行 `getUserMedia`，两边先后完成时 `store.voiceParsedEvents` 被后到者覆盖，先到的结果静默丢失。
2. **录音中离开行程页**：`VoiceInputButton` 随路由卸载 → `dispose()` 丢弃录音，用户无感知地丢失；转写进行中离开则无任何反馈，用户以为丢了。
3. **弹框内语音按钮无状态反馈**：静态 `el-button`，点击后录音是否开始、进行到哪一步完全不可感知。

根因：语音录入本质是**页面级、跨页面的事务**，却长在组件生命周期里。改造方向：状态机提升为**模块级单例**，两个入口变成同一台机器的两个控制面板，跨页面由全局浮标承接。

## 已确认的决策（需求方拍板）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 录音中点另一处入口 | **提示「语音录入进行中」拒绝开始**（不视为同一录音的停止操作） |
| 2 | 录音中离开行程页 | **录音继续 + 全局浮标**（见下） |
| 3 | 录音中关闭当日弹框 | **停止并提交已录内容**（default_date 仍是点击那天） |

### 全局浮标形态（已确认）

- 仅在**录音/识别未结束且用户不在行程页**时出现；行程页内由悬浮按钮承担，不重复显示
- 位置：右下角 `position: fixed`，与行程页悬浮麦克风同位（视觉上是同一控件"还在原地"）
- 两态：
  - 录音中：`● 正在录音 00:23  ✕ 结束` —— 红点呼吸动画、**录音时长计时器**、「结束」按钮（= 停止并提交转写）
  - 识别中：`◌ 语音识别中…` —— loading，不可操作
- 解析完成：浮标消失 + toast「语音已解析，回到『人员行程』确认」（任何页面）
- 挂载点：App.vue（与顶栏平级）；全屏路由（`isFullscreen`，如 /login）不渲染
- 极短录音（刚开口就关）仍走后端 422 提示，不特殊处理

## 目标

- 同一时刻物理上只有一条录音（单例状态机保证）
- 录音/识别状态在**所有页面**可见、可操作（浮标）或在本页控件上呈现（悬浮按钮/弹框按钮三态）
- 弹框内按钮与悬浮按钮同等的三态反馈：`语音录入` → `正在听·点击结束`（红色）→ `识别中…`（loading）
- 路由切换不再销毁录音；确认框仍在行程页打开（store 状态在，回去自然可见）

## 非目标（明确不做）

- 波形/音量动画
- 点浮标跳转回行程页（浮标只结束录音）
- 录音超长自动停止（计时器可见，用户自己关）
- 确认框跨页面弹出（仍在行程页）
- 后端改动（本改造纯前端；后端 default_date 链路已就绪）

## 约束

- 「人员」文案规范；`artist_id` 等接口字段名不动
- 验证：`npx vite build` 0 error（无前端组件测试设施）；录音行为需浏览器环境，代码走查 + 用户手测
- 现有防抖语义（idle→starting→recording→processing + 冷却期）必须保留

## 架构

```
useVoiceRecorder.js（模块级单例状态机）
  ├─ state: phase / startedAt / 来源标记（fab | dialog）
  ├─ 入口: start({ getDefaultDate, onResult }) —— 已在录音则 ElMessage 拒绝（决策 1）
  ├─ stop() / toggle() / dispose 语义收窄
  └─ store.voiceSaving 收编（防双写）

VoiceInputButton.vue（行程页悬浮 FAB）
  └─ 纯控制面板 + 三态渲染（现有样式不动）

DayDetailDrawer.vue（当日弹框）
  ├─ 语音按钮三态渲染（对齐悬浮按钮）
  └─ 弹框关闭时：录音中 → stop() 提交已录内容（决策 3）；识别中 → 不动，交给浮标

VoiceGlobalIndicator.vue（新组件，App.vue 挂载）
  └─ 仅当 phase ≠ idle 且路由 ≠ /itinerary 且非全屏路由时渲染
```

**决策 3 的实现要点**：关闭弹框时若 `phase === 'recording'` 调 `stop()`（走正常 onstop → 提交链路，`getDefaultDate` 此时取值仍是点击那天）；若 `phase === 'processing'` 什么都不做（axios 在跑，浮标接管展示）。

**store.voiceSaving**：现状两实例并发会互相踩；收进单例后天然只有一份写者，`VoiceConfirmDialog` 的 loading 绑定不变。

## 留给实现者的

- 单例的具体形式（模块级 `createSingleton()` vs 导出共享 ref 集合）——实现者按 Vue 惯例定
- 计时器：`startedAt` 时间戳 + 1s interval，每 tick 从 startedAt 重算（不累加），mm:ss；浮标卸载时清理
- toast 文案细节（语义不变前提下可微调）

## Builder check 补充裁决（评审后定稿）

评审发现若干缺口，按以下结论定稿（标注「我的裁定」的为实现层选择，需求方未逐条确认）：

1. **路由离开 + 弹框同开时谁赢**：**决策 2 赢**——路由离开（组件卸载）不算"用户关闭弹框"，录音继续交给浮标。停止提交只挂在 el-dialog 的 `@close`（用户显式关闭）上；组件卸载路径不调 stop。我的裁定：语义上"关弹框=收尾这条录音"只对用户主动行为成立。
2. **来源标记的语义**：只用于**弹框关闭时判断是否停止**（决策 3 仅作用于 dialog 来源的录音；FAB 来源的录音不因弹框关闭而停）。非来源入口在 recording 期间渲染为**禁用态 + tooltip「语音录入进行中」**，不渲染"点击结束"（决策 1 与渲染矛盾，以决策 1 为准）。拒绝重入覆盖 `starting` / `recording` / `processing` 全部非 idle 相位。
3. **default_date / artist 快照时机**：`start()` 时**快照**（不活在 store 上）——`initMonth()` 重挂载会把 selectedDate 重置为今天，现设计的"stop 时取值"在路由往返后是错的。default_artist_id 同理在 start 时快照。这同时覆盖兜底文件路径（选完文件回来时用录音发起时的日期/人员）。
4. **dispose 的去留**：对外 API 删除 dispose；单例内部保留硬复位（仅用于登出/鉴权失效）。无人再需要"组件卸载即销毁"。
5. **登出/鉴权失效中录音**：路由守卫切到 /login 时单例硬复位——停止并**丢弃**（不提交：token 已失效，提交必 401）。我的裁定：丢弃优先于提交。
6. **兜底文件路径纳入同一状态机**：`start()` 在 fallback 分支也置 `starting`（选文件即转 `processing`），防重入与快照对它同样生效；浮标对 starting 相位按录音态渲染（结束按钮禁用）。
7. **计时器时钟**：`Date.now()` 墙钟，接受后台 throttling 冻结/回跳（移动端切回后跳正是真实经过时长）。

「store.voiceSaving 收编」按评审读法修正为**无操作**：唯一写者本就是 store actions，单例化已消除并发写，不动 `VoiceConfirmDialog` 的现有绑定。
